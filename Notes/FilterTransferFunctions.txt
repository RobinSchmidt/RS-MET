We want to figure out a general way for how to find expressions for z-domain filter transfer 
functions for a given time domain filtering algorithm in the form of a set of difference equations.
The transfer function of a filter is the ratio of the z-transforms of the output signal and the 
input signal of the filter, i.e. H(z) = Y(z)/X(z). 


First Order Direct Form 1 filter
--------------------------------

Let's start with a very simple first order direct form 1 (DF1) filter as warm up. In this case, the 
derivation of H(z) = Y(z) / X(z) proceeds as follows:

  y[n] = b0*x[n] + b1*x[n-1] - a1*y[n-1]                Translate to z-domain

  Y(z) = b0*X(z) + b1*z^-1*X(z) - a1*z^-1*Y(z)          Move Y(z) terms to left and X(z) to right
  Y(z) + a1*z^-1*Y(z) = b0*X(z) + b1*z^-1*X(z)          Factor out Y and X
  Y(z) (1 + a1*z^-1) = X(z)  (b0 + b1*z^-1)             Solve for Y(z)/X(z) and call that H(z)

  H(z) = Y(z)/X(z) = (b0 + b1*z^-1) / (1 + a1*z^-1)     Done

That way easy enough and the procedure can be generalized to DF1 filters of arbitrary order. The 
order doesn't make it more complicated, just the polynomials will get longer.


First Order Direct Form 2 filter
--------------------------------

Let's as the next step try it with a direct form 2 (DF2) filter to see how to deal with intermediate 
variables. For the filter block diagram, see:
  
  https://www.dsprelated.com/freebooks/filters/Direct_Form_II.html

The time domain difference equations and z-domain algebraic equations look like this:

         Time domain                              z-domain

  v[n] = x[n] - a1*v[n-1]       <-->     V(z) = X(z) - a1*z^-1*V(z)
  y[n] = b0*v[n] + b1*v[n-1]    <-->     Y(z) = b0*V(z) + b1*z-^1*V(z)

To make things more easy to write, we will used the substitution d = z^-1 (you may read the d as
"delay") and suppress the argument, i.e. we will just write X,V,Y instead of X(z),V(z),Y(z). With
that in place, we can write for the z-domain equations:

  V = X - a1*V*d
  Y = b0*V + b1*V*d  

Again, we want to solve for Y/X. Let's solve the 1st equation for V:

  V + a1*V*d = X = V(1 + a1*d)  
  V = X / (1 + a1*d)

and plug that result into the 2nd equation:

  Y = b0*(X / (1 + a1*d)) + b1*(X / (1 + a1*d))*d 
    = (X / (1 + a1*d)) * (b0 + b1*d)
    = (b0 + b1*d)* X / (1 + a1*d)

And now divide both sides by X to get H = Y/X:

  H = Y/X = (b0 + b1*d) / (1 + a1*d) 
    = (b0 + b1*z^-1) / (1 + a1*z^-1)

which is the same result as it should be. Instead of doing it by hand, it makes sense to automate 
the job by handing is to a computer algebra system. The following code for SageMath produces the
solution:

var("b0 b1 a1 d X Y V H")       # b0,b1,a1: filter coeffs, d = z^-1, X=X(z),Y=Y(Z),etc.
e1 = V == X - a1*V*d            # 1st equation from the filter's state update
e2 = Y == b0*V + b1*V*d         # 2nd equation from the filter's output computation
V_X = solve([e1],[V])           # V_X =  [V == X/(a1*d + 1)], V in terms of X
e3  = e2.subs(V=V_X[0].rhs())   # e3  =  Y == X*b1*d/(a1*d + 1) + X*b0/(a1*d + 1)
e3  = e3.simplify_full()        # e3  =  Y == (X*b1*d + X*b0)/(a1*d + 1)
e4  = H == Y/X                  # Introduce auxiliary equation for H(z) = Y(z)/X(z)
sln = solve([e3,e4],[H,Y])      # solve([e3,e4],[H,X]) works also
sln[0][0]                       # Prints the solution: H == (b1*d + b0)/(a1*d + 1)

It is important to ask the solver to solve for [H,Y] and not just for [H] even though we are 
eventually only interested in H. But trying to just use  sln = solve([e3,e4],[H])  will not work.
It will produce an empty solution set. I guess it has to do with having two equations for one 
variable, i.e. 2 constraints and only 1 degree of freedom. The code snippet can be copy-and-pasted 
and executed here https://sagecell.sagemath.org/. It produces the desired output:

  H == (b1*d + b0)/(a1*d + 1)

Apparently, the solution sln is an array with two indices (Why? Wouldn't one index be enough?). The
second element is an expression for Y which we are not interested in. Just for info, it is:
Y == (X*b1*d + X*b0)/(a1*d + 1). That might actually be useful because one can read off the DF1 
implementation from it. The Sage code above can be simplified. We don't really need to do the 
intermediate solutions, substitution and simplifcations manually to get down to one equation plus
our auxiliary. This code here also works:

var("b0 b1 a1 d X Y V H")         # b0,b1,a1: filter coeffs, d = z^-1, X=X(z),Y=Y(Z),etc.
e1 = V == X - a1*V*d              # 1st equation from the filter's state update
e2 = Y == b0*V + b1*V*d           # 2nd equation from the filter's output computation
e3 = H == Y/X                     # Auxiliary equation for H(z) = Y(z)/X(z)
sln = solve([e1,e2,e3],[H,X,Y])   # Solve the system of equations 
sln[0][0]                         # The 1st element is what we are interested in

Here, we used the original 2 equations and introduced the auxiliary H = Y/X equation as 3rd equation 
and solved for 3 variables H,X,Y. Again, we are mainly interested in H.


Moog Ladder with Unit Delay Feedback (UDF)
------------------------------------------

As the next example, let's have a look at a Moog-style ladder filter that is built from 4 one
pole filters with a feedback loop that includes a unit delay. We define the difference equation and
transfer function of the 1-pole as:

  g1[n] = b0*x[n] - a1*g1[n-1]      <-->    G1(z) = b0 / (1 + a1*z-^1)

Four of such filters in series give G4(z) = (G1(z))^4:

  G4(z) = (b0 / (1 + a1*z-^1))^4  
        = (b0 / (1 + a1*d))^4

We could expand this but it turns out to be more convenient to leave it in this form. The complete
transfer function with feedback is given by:

  H(z) = G4(z) / (1 + k*z^-1*G4(z))   or more tersely   H = G4 / (1 + k*d*G4)

This is implemented in rsLadderFilter::getTransferFunctionAt() but with additional mixing of the 
filter output stages (which is an add-on functionality that this filter has to obtain response
types other than 4th order lowpass).
