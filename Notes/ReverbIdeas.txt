Delayline lengths for Feedback Delay Networks (FDNs)

In this section, I collect some considerations and ideas for tuning the lengths of the delay lines
in an FDN.

- The classic literature says that the lenghts M1,M2,M3,... should be mutually coprime in order to
  avoid recirculating impulses to line up in time as much as possible.

- Beyond that "mutually comprime" condition for M1,M2,..., could it perhaps make sense to also have
  M1+M1, M1+M2, M1+M2, ..., M2+M2, M2+M3, ..., i.e. all possible different pairwise sums also 
  mutually coprime? And maybe also all the possible triple-wise sums etc.? Just an idea. Try it!

- In order to systematically explore the space of different length tunings, we should try to find a
  suitable objective function to optimize. We want a function into which we can plug in the lengths
  and it returns a number that tells us how good that configuration is. The results that this 
  fitness function produces should correlate well with human perception. Some featues that are known
  to correlate well with perceived reverb quality are modal density, echo density, ...TBC...

- When we have established such a fitness function and experimentally verified that indeed captures
  quality perception reasonably well, we can use that in an automated search for good tunings. Maybe
  we can use evolutionary algorithms for that.

- Ideally, a lossless prototype network should produce an impulse response that is similar to white 
  noise. In an FDN, this amount of complexity will typically only happen after some time when the 
  impulses have completed some number of roundtrips. Before that, we will see isolated echos. But 
  that's actually realistic, though, so it might not be that much of a problem.

- We want the spectrum to be white with no ringing modes standing out so maybe the fitness function
  should be based on how flat the spectrum is. If we view it as cost function to be minimized, a 
  completely flat spectrum should give a value of zero and deviations from flatness should increase
  the value. Maybe such a function could work as follows: Compute the dB-spectrum. Compute the 
  average (aka mean) dB-value of the spectrum. Compute the sum of (some power of) the absolute 
  values of the deviations from the mean dB value. Maybe the power could be different for positive 
  and negative deviations reflecting the fact that notches are less annoying than resonances. Maybe
  we should not only take the heights of the deviations into account but also their widths. Narrow
  resonances (and maybe also antiresonances) turn up as ringing whioch is what we want to penalize.
  Maybe we should look at my idea for a "ringing response" instead of the magnitude response. See
  experiments in the main repo.

- Maybe the fitness function should contain two terms. One for the spectral features that penalizes
  deviations from flatness and one for temporal features that penalizes echo collisions. Maybe we
  should minimize the maximum distance between modal frequencies together with the maximum distance
  between (early?) echoes. But what do we mean by "early"? Maybe we should express this in terms of
  passes through the feedback loop. Take the length m_max of the longest delayline and then define
  1st order echoes as those occurring for n <= m_max, 1st-and-2nd order echoes as those for 
  n <= 2*m_max, etc. In general, up to k-th order echoes are those occurring for n <= k*m_max. With
  that definition in place, we can define "early" in terms of the chosen k. Early should mean a 
  small k. Maybe something in 1..5? But maybe that should depend on the number of delaylines. I 
  think, with more delaylines, we reach echo pattern complexity faster (i.e. with fewer passes
  through the feedback loop), so maybe for more delaylines, we should choose a smaller k.

- We want to develop an algorithm into which we can plug in a range min..max and it returns an array
  of monotonically increasing lengths within that range. Naively, we could use an equidistant (or 
  linear) spacing or an exponential spacing. In some first experiments that I did long ago, this 
  naive approach led to bad sounding reverbs, though. So, simple linear and exponential spacings 
  seem not to be good. 
  
- Somewhere in RAPT, I have a class rsRatioGenerator that is made for this purpose. It has already
  some more interesting algorithms implemented. New algorithms and formulas should be added to that
  class. The ratios that this class produces can be used for delay lines in FDNs but also for 
  frequencies in supersaws and maybe in other contexts as well.

- Maybe we should try a spacing in which the reciprocals of the lengths are linearly spaced. The 
  rationale is that reciprocals of lengths correspond to modal frequencies (verify!) and I think, 
  that we ultimately want to spread these modal frequencies equally around the unit circle. 
  Although, we may actually want to have the modal density increase with frequency, so maybe the 
  length distribution should be skewed toward shorter lengths.

- Maybe it makes sense to let the longer lengths be tuned such that their produced modes correspond 
  to musical frequencies. For example, when the song is in A minor, we may want to have a low mode
  at 55 Hz. Maybe we should let the user tune the low modes in terms of musical pitches.

- Maybe try creating a 4x4 FDN with modal frequencies tunes to A,C,E,G and use it on a sound played
  in A minor. Maybe try also an 8x8 FDN with A,C,E,G,B,D,F,A spanning 2 octaves or just go up the
  scale A,B,C,D,E,F,G. Allow the user to select the scale (major, minor, aeolian, lydian, etc.). 
  Maybe call the module ScaleVerb. Maybe allow custom scales maybe by importing .tun files. Have an
  overall Tuning parameter. Let the user switch between 4x4, 8x8 and maybe 6x6, 12x12.

Time variance

In this section, I collect some ideas for how to incorporate time variance (i.e. modulation) into
the reverb.

- I think, the classic way to introduce some modulation is to vary the delayline lengths over time
  which should create some sort of chorusy effect and helps to fight against a metallic sound due to
  single modes standing out.

- Maybe place modulated allpasses into the loop, directly after the delaylines, before the feedback
  matrix. Try 1st and 2nd order allpasses, Schroeder allpasses, allpass dispersers, etc. I think, a
  1st order allpass is like modulating the delayline length by at most one sample using allpass 
  interpolation (verify!).

- Specifically for an FDN using my generalized Hadamard transform as feedback matrix, we could try
  to modulate the angle parameter phi

- Because I like my effect algorithms to be autonomous, i.e. not requiring some external modulation
  source like an LFO, we could try to derive a modulation signal directly from the signals that we
  already have (input, output, internal state). Passing those through a bandpass could give us a
  sine-LFO-like signal. Before the bandpass, we could also do stuff like taking the absolute value,
  squaring, taking another power, multiplying different signals together, etc. The goal of this is 
  to produce an overtone-rich (ideally noise-like) signal, because a noise-driven bandpass makes for
  a good modulator. 
  Q: Should these operations should be linear such that f(a*x) = a*f(x)? I think this holds for the 
  absolute value. ...but it is normally considered nonlinear. Maybe we only need the "homogeneous"
  part of linearity but not the "additive" part. Abs does not satisfy f(x+y) = f(x) + f(y). But I 
  think, a homogeneous operation would mean that the modulation goes down when the signal goes 
  quiet. This may or may not be desirable. We'll see. Maybe it would be desirable that the amount of 
  modulation is independent of the volume of the input signal. Maybe we can achieve this by using 
  an envelope follower and renormalize our signals by the detected envelope (i.e. divide by it).

Nonlinearities

In this section, I collect some ideas for how to integrate nonlinearities into the reverb.

- Gating the wet output for the classic "gated reverb" sound.

- Ducking the wet signal by the input in order to get clean and dry transients together with a 
  reverberant tail.

- We could try to have some sort of dynamics processor in the feedback path in order to try to 
  achieve different decay shapes. The standard decay shape is exponential but it may be interesting
  to try to modify that default shape.

  - To implement this, we could scale all the feedback gains by a common gain factor g that gets 
    computed in such a way to scale the overall decay time by some factor k. Or maybe each feedback
    gain needs its own scaler? We'll see.
  
  - The decay time factor k may be computed from the total energy (or sum of abs values) that is 
    currently stored in the state of the system. But we do not want to run a sum over the complete
    delayline contents at every sample. Maybe we can update this sum recursively from a known value
    at the previous sample and our knowledge about how we have modified the state at the current 
    sample. In all the delaylines, we replace one value. We just need to take the old sum and for
    each delayline, subtract the value of the old delayline sample (the one that got replaced) and 
    add the new delayline sample (the replacement value).
  
  - See this thread:
    Delay/Reverb with Compressor in feedback path, secret sauce?
    https://www.kvraudio.com/forum/viewtopic.php?t=634777

- A pitch shifter in the feedback path could be interesting. Or maybe a frequency shifter.

- A phase distortion algorithm in the feedback path could create a sort of "bloom" effect in the 
  sense that more passes through the loop make the signal progressively richer in overtones. See:
  Someone should make this plugin. Cymbal synthesis.
  https://www.kvraudio.com/forum/viewtopic.php?p=9233715
